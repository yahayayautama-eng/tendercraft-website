Still-Lane privacy policy

Updated 21 October 2026. This policy describes the current Windows app and background tracker.

Local collection and storage

Recording begins after you choose Start tracking. Still-Lane stores its records on your PC in a local SQLite database, focus-tracker.db. The installed Store package uses its own Windows package LocalState folder. The Status tab shows the database path.

Still-Lane has no accounts, analytics, advertising or telemetry code. Its app and agent do not make network requests or upload your records. They communicate through a local Windows named pipe. Windows, the Microsoft Store and separately installed platform software operate under their own policies; this policy describes Still-Lane's collection.

The database contains:

  • Application program paths and display names, with the category, exclusion, daily and weekday limits, passive-use exemption and focus-reminder choices you set for each app.
  • Foreground interval start and end times, the recorded time-zone offset, active or idle state, and the reason an interval ended, such as switching apps, inactivity, lock, sleep or pause.
  • A recovery record for the current interval, including its last-seen time, to handle an unexpected shutdown.
  • Category names, optional category colours and category daily limits.
  • Focus session start, planned end, actual end when available, and end reason.
  • Scheduled focus days, local start times, lengths and enabled states, with a date marker to prevent duplicate starts.
  • Reminder allowances and their expiry times, saved across tracker restarts.
  • Settings, including the time you consented to recording, whether tracking is paused, your appearance choice, your retention period, and if you use the optional water break, its on/off choice, interval and today's glass count. Windows manages the start-at-sign-in preference separately, your water break preference and today's glass count.
  • Small program icons, copied from the program files of apps you use and saved as pictures in an icons folder beside the database, so lists can show them. They contain no usage information and are removed by Delete all data.

Still-Lane does not read or record window titles, document names, web addresses or URLs, keystrokes, screenshots or screen contents. It checks the time since the last input to estimate inactivity, without reading what you type. Only a playing Windows media session matching the app in front suppresses inactivity. You can choose “Count time as active even without keyboard or mouse” for an app you watch or read. Media titles and content are not saved. App paths can contain your Windows user name or other names you have chosen for folders and program files.

Diagnostic log

The agent writes agent.log beside the database. It holds dated operational events, including lock, power, pause and focus-session times, recovery events, reminder choices, retention counts and errors. Normal log messages do not include tracked app names or program paths. Before writing any message, the agent replaces your Windows user profile path with %USERPROFILE%, regardless of letter case. Other text is unchanged, so errors may still contain app names, paths outside that profile, or other diagnostic details.

After each successful write, the log is at most 1 MiB (1,048,576 bytes). The agent clears the existing log before writing an entry that would cross that limit. A single entry larger than the limit is shortened to fit, keeping valid UTF-8 text and a line ending. The log is not subject to the history retention setting. Delete all data attempts to remove the log and stops further logging by that agent; if Windows prevents deletion, a log may remain.

The Status page offers Copy diagnostic info. It copies version/platform information, tracker state, schema, record counts, retention days and up to 50 sanitized log entries to your clipboard. Log timestamps and variable details are removed; app names, paths, window titles and usage times are omitted. Nothing is sent automatically. Review the text before sharing it.

Retention and your controls

The default retention period is 90 days, configurable in Data controls. The app deletes usage intervals that ended before the cutoff when the tracker starts, hourly while it runs, and when you change retention in the window. This retention rule applies to usage intervals only. Focus sessions, app identities, categories, rules, settings and the recovery record are not removed by that rule.

You can:

  • Pause and resume recording from the window or tray menu. Closing the window leaves the background tracker running; Quit in the tray stops it.
  • Exclude an app in Apps & limits. This deletes that app's saved intervals and recovery record and prevents future recording until you enable it again. Its identity and exclusion choice remain so the tracker can recognize it.
  • Delete one app's history. This removes its saved intervals and recovery record, while keeping its identity and rules. Tracking continues from that point unless you also exclude it.
  • Export saved usage intervals and focus sessions as JSON or CSV in Data controls. JSON contains intervals, focusSessions and focusSchedules; CSV writes a usage file and a second -focus-sessions.csv file. These exports do not include the diagnostic log or a separate inventory of all settings, exclusions, app rules and category limits. Choose an export location carefully; exported files are independent copies.
  • Choose Delete all data to stop the tracker, remove all database records (including consent, settings and focus sessions), compact the database, and attempt to remove the log. The window returns to setup. The empty database file may remain. Copies you exported or backed up are not deleted.

Removing the installed Store package normally removes its package-local database and log with the package data. Keeping app data through Windows or an uninstall tool, or making external copies, can preserve those copies.

Records use the normal Windows per-user storage permissions. For help with data controls, see Support.
